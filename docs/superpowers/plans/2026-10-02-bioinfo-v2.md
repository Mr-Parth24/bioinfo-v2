# Bioinfo version 2 implementation plan

> Execute inline using superpowers:executing-plans. Preserve source and keep changes local.

**Goal:** A reviewable, dockerized lab website with preserved information and structured editing.
**Architecture:** Offline migration to JSON, Node 24 server-rendered public pages, SQLite content/revisions and authenticated editor.
**Spec:** ../specs/2026-10-02-bioinfo-v2-design.md

## Global constraints

- Keep all original information and tool destinations; source remains untouched.
- No external downloads required to build/test core functionality.
- No default credentials. Production admin requires HTTPS.
- Flag conflicting source facts. No invented replacements.

## Review focus

1. Missing/orphaned source content and external links mistaken for local pages.
2. Stored HTML/URL injection, cookie/CSRF bypass and path traversal.
3. Restart persistence, draft visibility and lost concurrent edits.
4. Broken remote images, mobile overflow and keyboard access.
5. Content updates and Docker rebuilds must preserve data and uploaded images.

## Tasks

1. Migration: scripts/migrate.py parses source literals without executing code, imports article bodies, preserves provenance and emits content/seed.json plus docs/migration-report.json. Test count preservation, URLs and malformed known source entry repair with Python unittest.
2. Backend: src/content.mjs validates schemas, src/store.mjs persists via SQLite, src/security.mjs handles sessions/sanitization. Node tests cover invalid input, round trips, revisions, drafts and authentication.
3. Public UI: src/render.mjs and public/site.css/site.js produce all routes and responsive searchable directories. Tests enumerate routes, validate links and fallback behavior. scripts/export-preview.mjs creates a portable review export.
4. Editor and delivery: src/app.mjs/src/server.mjs, public/admin.js and scripts/manage.mjs provide login, editor, uploads and CLI. Tests drive Request/Response handlers for auth/CSRF/save/publish/upload. Add Docker/Compose and operator instructions.
5. Run complete test suite, check exported pages, inspect browser output if permitted, and review changes. Record remaining access blockers rather than claiming unperformed checks.
